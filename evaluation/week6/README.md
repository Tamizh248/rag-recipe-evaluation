# Week 6 — Validating the Substitution Judge

## What's built (all real, all run against the actual app)

- **Substitution feature** (`backend/app/substitution/`): a fixed
  ingredient/diet substitution table + allergen table (`tables.py`, same
  non-invention discipline as the sample rag-poc project's
  `app/agent/tools.py`), a `SubstitutionService` that grounds every request
  directly against one recipe's own stored chunks (never similarity
  search), and `POST /api/substitute`.
- **26 substitution cases + 2 regression cases** (`backend/evals/cases.py`)
  — run with `python scripts/run_week6_eval.py` (one command, pass rate by
  mode). Currently: 26/26 substitution cases pass; the 2 regression cases
  (pinned to real Week-5 traces) still correctly fail, since the
  underlying Week-5 chat-pipeline bugs (header-line-as-answer,
  wrong-recipe-citation) haven't been fixed — that's an honest report, not
  a bug in this harness.
- **5 deterministic assertions** (`backend/evals/assertions.py`) —
  moved out of the judge entirely: substitute appears consistently in
  both the ingredient list and method text, oven temp carries units,
  quantities parse as numbers, the allergen line matches a
  deterministically recomputed ground truth, and servings are echoed.
- **Judge v1** (`backend/evals/judge.py`, described exactly in
  `judge_v1.txt`) — the ONE remaining criterion: is this substitution (or
  refusal) safe and correct? Real Claude call if `LLM_PROVIDER=anthropic`;
  otherwise a disclosed, deliberately imperfect keyword heuristic (no local
  LLM ships with this project to judge with, same honest-stand-in pattern
  as `LocalExtractiveProvider`) — its known blind spots are written out in
  `judge_v1.txt`.
- **Blind-review material** (`blind_review.json`, real output from all 26
  cases, generated by `python scripts/generate_week6_blind_review.py`) and
  a blank **`labels_25.json`** template for you to fill in.

## What's left for you, IN THIS ORDER

1. Open `blind_review.json`, read each of the 26 cases, and fill in
   `labels_25.json`'s `label_pass` (true/false) yourself — **without**
   running the judge first. Commit `labels_25.json` on its own; the commit
   hash/timestamp is what proves the ordering.
2. Run `python scripts/run_week6_judge.py`. It refuses to run if any label
   is still blank. It prints `agreement_before` and every DISAGREE case.
3. Write your one-sentence prediction in `prediction.txt` — what you think
   fixing 2 of those disagreements will do to the judge — BEFORE editing
   `evals/judge.py`.
4. Pick 2 real disagreements, decide who was right, edit
   `_heuristic_judge` (or `JUDGE_PROMPT` if using `LLM_PROVIDER=anthropic`)
   to fix that specific blind spot, and write what changed in
   `judge_v2.txt`.
5. Re-run `python scripts/run_week6_judge.py` for `agreement_after`, and
   fill in the rest of `prediction.txt` and `judge_v2.txt`.
